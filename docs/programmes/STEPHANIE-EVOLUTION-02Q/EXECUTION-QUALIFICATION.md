# SE2Q-D/E/F/G — Execution qualification

Three new synthetic development tasks were frozen separately from the eight SE2 investigation prompts. They exercised missing-response evidence, complete JSON-fence normalization rules, and structure-versus-evidence validation. Output schema is four compact fields: findings, unknowns, next step, and evidence IDs; no answer key or semantic acceptance labels were sent to either model route.

The first three direct AI readiness tasks used the exact `ornith-1.5:9b` local tag, `InferenceService.generate()` with Ollama native `format` JSON Schema, 512 requested output tokens, and a 60-second timeout; Stephanie then parsed and validated the returned body. All three were valid against Stephanie's `ReadinessAnswer`; each cited only evidence IDs supplied with that task. Provider reported 327–337 input and 129–134 output tokens; `done_reason=stop`. A separately frozen one-call probe then exercised the exact `InferenceService.generate_structured()` caller path on a development task and passed, with 399 input /129 output tokens, 7.777 seconds, and `done_reason=stop`. Raw responses, fingerprints, usage, and metadata are retained. The probe narrows the API-path uncertainty but is only one successful task and does not establish the cause of SE2's 24 malformed results.

Worker used a separate in-process source runtime, HTTP loopback port, custom run-local model route, isolated execution ledger, and disabled global usage/evidence ledgers. The process accepted no workspace or tools and bound `127.0.0.1`. The isolated service was stopped after each diagnostic lane. Its structured JSON validator and adaptive strategy preserved actual outputs and H3 records. A single fenced-output and bounded-correction unit test each passed in the read-only Worker checkout.

The initial Worker 512-token response ended inside a JSON string with reported output usage exactly 512. That is direct evidence of incomplete output at the requested ceiling and strong support for a budget interaction on that one task; Worker/OpenCode did not retain a provider `finish_reason`, so the termination reason itself remains unknown. At 1,024 tokens the same Worker task produced a complete response with 533 reported output tokens. A second task returned no output, leaving the provider's inference execution unknown. Thus output budget explains one observed failure; it does not explain the historical 24 or the later empty output.

The deterministic fence-normalization and one-correction controls are covered by existing Worker tests. Live Worker demonstrated the `adaptive.v1` valid-output path but did not qualify reliable completion across the three tasks. Direct AI is qualified for the limited development readiness contract, not semantic effectiveness or a future protected study. Independent review also found the original frozen schema lacks the later-added Pydantic minima; those minima are enforced at runtime, while aligned schema v2 was used for the exact-API probe.
