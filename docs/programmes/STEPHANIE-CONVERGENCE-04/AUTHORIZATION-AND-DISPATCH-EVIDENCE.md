# Authorization and dispatch evidence

The Mission experiment decision reuses the existing Work Corrective proposal. Revising its scope bumps the proposal version and resets it to `draft`; a human must move it through `ready_for_review` to `approved`. The scope is canonical and pins Mission finding/source, Stephanie investigation, candidate and candidate digest, experiment, protocol digest, resource limits, and Work Objective/version/digest. Production promotion is explicitly excluded.

Before dispatch, the server verifies the persisted proposal scope/hash, current source and objective, exact frozen artifacts, active Work Envelope, proposal authorization reference, originating finding, and envelope commission digest recomputed from the approved scope and acceptance criteria. `EnvelopeService.reserve_stephanie_dispatch` locks the proposal row and atomically advances `approved → queued → running` while creating a Work Outcome execution link. Proposal cancellation and scope edits are refused while that execution claim is running.

Mission and Stephanie each keep an exclusive run claim. A claim with uncertain state is never re-executed. Reconciliation accepts a completed result only when Stephanie's SC3 claim pins the `integrated-results.json` digest, the actual isolated Worker ledger matches its saved digest, and Mission's outer claim matches the full result digest. A verified result updates the existing Work Outcome link and records `running → reported_complete`; it does not mark the Work Objective satisfied or accept/promote the candidate.

The focused and explicit long integration tests cover missing approval, mismatched investigation, candidate/protocol digest mismatch, duplicate dispatch reconciliation, and tampered Worker-ledger result refusal. Other SC3 tests cover Worker execution failure, evaluator absence, invalid-candidate rejection, Praxis insufficient evidence/regression, and additional-compute withholding. The full commissioned negative-control matrix and a browser workflow are still outstanding, so these controls do not close SC4B in full.
