# Free-first routing implementation

**Status: deterministic foundation implemented; live SIS chat remains disabled.** `config/sis.yaml` keeps `chat_runtime.enabled: false` and both model/persistence readiness flags false. The free-first policy is wired into `LLMService.achat`, the existing async SIS chat path. It reuses LiteLLM, bounded ChatContext messages and ChatStore; it does not create another chat database or use Worker as a chat proxy.

Configured order is OpenCode Console `deepseek-v4.1-flash-free`, then `hy4-flash-free`, both explicitly marked free and allowed for `personal`/`public` data based on the cited current OpenCode policy. SIS chat currently requires only the `conversation` capability. Routes lacking configured data-class/capability eligibility are not called. This metadata is an operator allowlist, not a discovered model registry or proof of coding/review capabilities. Data class is currently configured per SIS runtime, not selected per turn; do not enable live chat for confidential source or protected evaluation material until per-turn privacy classification/local-only routing is added.

Each eligible route is attempted at most once per turn. 429 responses are classified as rate-limited or allocation-exhausted; numeric `Retry-After`, HTTP-date `Retry-After`, and standard `RateLimit-Reset` delay values are honored where supplied. If absent, a configured local 60-second cooldown prevents repeated attempts; it does not claim to be the provider reset. Model 404 and provider/transport unavailability may proceed to the next eligible free route. After free routes fail, the already configured local Ollama chat route may be used and routing metadata records why. Missing OpenCode credentials can use this explicit local fallback without sending a request. Provider authentication/permission errors, unsupported capability, and unknown failures stop and fail closed. No subscription/metered route is configured. The owner/operator can pin an exact allowlisted free route through `chat_runtime.routing.pinned_route`; the pin is attempted alone and fails closed without automatic model switching. Existing explicit LLM overrides and pinned experiment input bypass this chat selector.

The router never retries an individual route. It forwards the exact supplied messages, preserving continuity as ChatStore changes or the underlying model changes. Prompt and response remain in the existing ChatStore when SIS persists the turn. LiteLLM call-level metadata provides selected model, usage and response ID; route-failure summaries do not record prompt text or credentials.

Focused tests: `tests/test_free_first_chat.py` and two neighboring SIS chat/provenance tests; 13 passed in the latest run (8.85 seconds including pytest startup, slowest test 0.02 seconds). None is marked long. No provider invocation was made in these tests. Not yet qualified: genuine OpenCode API endpoint invocation, project context retrieval, coding/review capability, cross-process cooldown persistence, live ChatStore restart/persistence with this route, user-selectable UI pins, paid escalation, nor full conversational operation. Those remain future inputs; chat activation stays off.
