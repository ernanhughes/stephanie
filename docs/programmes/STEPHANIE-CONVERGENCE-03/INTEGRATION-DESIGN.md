# SC3 Integration Design

Stephanie uses one once-only call to existing shared `ai.inference` to generate a structured hypothesis from sanitized Worker source facts. Raw response, provider metadata, usage, and failure evidence remain in Stephanie's existing AI evidence artifact. The hypothesis digest is bound into the frozen candidate and protocol. Stephanie then invokes the existing Worker HTTP service in an isolated process. Worker owns strategy execution and its execution ledger. A separately frozen exact-answer evaluator scores saved outputs and is excluded from AI/Worker context. Stephanie passes populated observations to Praxis `compare_effectiveness`; it records the returned comparison and applies a resource-confounding hold where Praxis does not account for invocation counts. Stephanie stores experiment references in its existing ExperimentStore and CaseBookStore. Mission Control remained read-only; no formal acceptance is asserted.

The deterministic runner imports the existing Worker `WorkerService`, HTTP server, executor registry, model runtime, strategy runtime, and execution ledger. It registers a scripted fixture provider. The live runner uses the same Worker request and HTTP path with the already installed local-only model route. Neither runner writes operational storage. The evaluator is a separate local artifact and its answer is not included in Worker requests.

Ownership: AI provides shared inference interfaces; Stephanie owns experiment coordination and experience; Worker owns execution and evidence; Praxis owns comparisons; Mission owns operational authorization and acceptance. SC3 does not implement promotion or a duplicate service.
