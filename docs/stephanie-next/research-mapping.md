## Synthesis for Stephanie

1. **First create trustworthy execution records.** ChatStore handles conversation content; PlanTrace handles pipeline traces; runtime runs need explicit IDs/status/evidence links. This precedes useful retrieval or improvement.
2. **Measure the learning process, not only final scores.** Keep fixed baselines, development/held-out/transfer task identities, costs, regression/rollback and retrieval/use attribution.
3. **Keep evaluator authority separate.** Improvement authors cannot mutate the evaluation protocol or held-out set; use executable tests and source-grounded checks where available.
4. **Bound the mutation scope.** Begin with prompt/context/skill/config artifacts, not global runtime source or foundation-model weights.
5. **Do not implement a paper per module.** Existing ExperimentStore, MetricStore, PlanTrace, CaseBooks, MemCube, skill agents, scoring and Hydra mutation already cover much of the infrastructure. New functionality should be a small integration/protocol only when a verifiable capability is missing.
